# Публикация и управление приложением

## 1. Проверьте прототип

Откройте index.html в папке mobile. Пройдите CHECKLIST.md. Родительские файлы сайта и паспорт не менялись.

Покажите приложение 3–5 участникам: могут ли они без подсказки найти полезного человека, понять взнос, записаться и оставить мысль?

## 2. Создайте репозиторий

1. Войдите на https://github.com.
2. Нажмите «+» → New repository.
3. Назовите репозиторий tochka-rosta.
4. Для бесплатной публикации Pages выберите Public: код станет общедоступным.
5. Включите Add README, нажмите Create repository.

GitHub хранит файлы и историю. GitHub Pages публикует приложение по интернет-адресу.

## 3. Загрузите файлы

В репозитории нажмите Add file → Upload files. Загрузите СОДЕРЖИМОЕ папки mobile в корень: index.html должен находиться сразу в репозитории, а не в подпапке.

Обязательны index.html, app.css, app.js, data.js, manifest.webmanifest, sw.js, icon.svg, icon-192.png, icon-512.png. Добавьте README.md, GUIDE.md, CHECKLIST.md, .gitignore и .nojekyll. Скрытые файлы можно создать через Add file → Create new file. Для работы этого прототипа они необязательны.

Сообщение коммита: «Первый мобильный прототип». Нажмите Commit changes.

Не загружайте всю родительскую папку, паспорт, реальные контакты или секреты Telegram. Если загрузить саму папку mobile, адрес приложения будет оканчиваться на /mobile/; далее предполагается index.html в корне.

## 4. Включите публичную ссылку

1. Settings → Pages.
2. Build and deployment → Source → Deploy from a branch.
3. Branch → main, папка /(root).
4. Save.
5. Дождитесь публикации. Статус — во вкладке Actions и разделе Pages.
6. Откройте показанную ссылку: обычно https://ВАШ-ЛОГИН.github.io/tochka-rosta/.

При 404 проверьте расположение index.html, ветку и статус сборки. Публикация занимает несколько минут. Доступность Pages для приватных репозиториев зависит от тарифа; сам опубликованный сайт общедоступен.

Официальная инструкция:
https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## 5. Добавьте на телефон

Откройте опубликованный HTTPS-адрес:
- iPhone: Safari → «Поделиться» → «На экран Домой».
- Android: Chrome → меню → «Установить приложение» или «Добавить на главный экран».

Названия команд зависят от браузера. Сначала откройте с интернетом, затем проверьте повторный запуск без сети. Это PWA, а не публикация в магазинах приложений. Между устройствами данные пока не синхронизируются.

https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable

## 6. Ведите задачи

Создавайте Issues: одна задача — один результат и способ проверки. Например:
- Утвердить расчёт взноса, момент оплаты и отмены.
- Собрать карточки с согласия участников.
- Подключить Telegram-вход.
- Создать базу событий и записей.
- Добавить админку.
- Загрузить фото.

Для общей доски используйте GitHub Projects: «Нужно сделать», «В работе», «Проверяем», «Готово».

## 7. Обновляйте приложение

Для разовой правки откройте data.js на GitHub и нажмите карандаш. Для постоянной работы удобно использовать GitHub Desktop: клонировать репозиторий и открыть его папку в редакторе.

Рабочий цикл:
1. Создать Issue.
2. Создать ветку, например feature/events-copy.
3. Внести изменение и проверить локально.
4. Увеличить VERSION в sw.js.
5. Сохранить коммит с понятным названием.
6. Отправить ветку на GitHub и открыть Pull request в main.
7. Просмотреть изменения и пройти CHECKLIST.md.
8. Merge pull request.
9. Дождаться Pages и проверить приложение на телефоне.

Коммит — сохранённый шаг истории. Ветка — место работы над изменением. Pull request — предложение перенести его в основную версию. Merge — принятие предложения.

Pages публикует main. Отдельная ветка не получает адрес предпросмотра автоматически; проверяйте её локально. Работайте с папкой клонированного репозитория, а не со старой копией.

## 8. Откатывайте ошибки

В объединённом pull request нажмите Revert, если кнопка доступна. Создайте и объедините обратный pull request, дождитесь повторной публикации. Revert создаёт коммит отмены, сохраняя историю.

Опечатки исправляйте новым коммитом. Для вех создавайте Release с тегом v0.1.0 или v0.2.0 и описанием изменений. Публикация Pages по-прежнему зависит от main.

https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/incorporating-changes-from-a-pull-request/reverting-a-pull-request

## 9. Подготовьте настоящую версию

Pages обслуживает статические файлы. Для общего сообщества нужен сервер:

1. Решить: клуб открытый или по заявке; видимость профилей; город; администраторы; порядок оплаты и возвратов.
2. Собрать 25–40 карточек, 3–4 события, 2–3 альбома — пороги из паспорта.
3. Подключить сервер и базу: участники, профили, книги, события, записи, реплики, фото. Свободные места проверять на сервере, чтобы два человека не заняли последнее место.
4. Реализовать Telegram-вход с серверной проверкой. Секрет бота хранить на сервере, не в публичном коде.
5. Реализовать публичные карточки, приватные контакты, права организатора, настройки видимости и согласия.
6. Добавить админку: расписание, книга, модерация, отметки оплаты и посещения. Этап 1 — ссылка на оплату и ручная отметка.
7. Затем подключить бот с напоминаниями и дайджестом.
8. Провести пилот, проверить резервное копирование и восстановление, затем запускать клуб.

Выбор сервера и базы зависит от бюджета, страны хранения данных и аудитории. Форум, наставники и личный прогресс — следующие этапы.

Оценивайте понятность записи и взноса, реплики между встречами, возврат на вторую встречу и сокращение ручной работы организатора. Показатели паспорта — ориентиры, не достигнутые результаты.
